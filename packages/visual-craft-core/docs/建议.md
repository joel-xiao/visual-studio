# Visual Craft Core 架构评估与改进建议

## 1. 目录结构评估 (Directory Structure)

### 现状分析
- **层级清晰**：`canvas/` (视图层), `hooks/` (逻辑层), `schema/` (数据定义) 职责分离明确。
- **模块化**：逻辑被有效拆分到了 `node-context`, `component-context` 等独立文件夹。

### 改进建议
- **逻辑目录更名 (Services vs Hooks)**：
  - 目前 `hooks/` 目录下大量代码是 `CreateNodeContext` 等类。建议参考领域驱动设计 (DDD)，将管理状态的类移至 `services/` 或 `store/` 目录。
  - `hooks/` 仅保留用于连接组件与服务的 Vue Composition API。
- **数据规约去 UI 化**：
  - 将 `schema` 定义从 `views/editor/` 移至根目录或 `src/core/` 级别。
  - 这是为了支持多平台（预览页、H5 端、SSR）时，数据模型不依赖于特定的 UI 视图。

## 2. 代码逻辑设计评估 (Logic Design)

### 优势
- **单例 Context 模式**：使用 Class 管理状态并导出单例 Hook，比单一状态库更容易处理复杂的引用关系，且利于 IDE 类型追踪。
- **职责解耦**：将 Group 等扩展功能独立出 `group.ts`，保证了核心代码的精简。

### 核心改进方案

#### A. 引入事件总线 (Event Bus) 解耦视图
- **现状**：`CreateNodeContext` 通过 `#nodeInstances` 直接操作组件方法（如 `setActive`）。
- **建议**：Service 应发布 `NODE_SELECTION_CHANGE` 事件，组件自行订阅并更新。实现 Service 的“无头 (Headless)”化，有利于单元测试。

#### B. 引入命令模式 (Command Pattern) 支持撤销重做
- **建议**：在此层级引入 **Undo/Redo**。目前直接修改数据无法记录操作历史。
- **方案**：使用 **Immer.js** 生成数据补丁，或者将 `updateNode` 封装为 Command 对象。

#### C. 空间索引优化潜力 (Spatial Indexing)（已完成）
- **现状**：框选逻辑使用 $O(n)$ 全扫描。
- **建议**：当页面节点增多时会产生性能瓶颈。建议引入 **R-Tree (如 rbush 库)**，将框选复杂度降至 $O(\log n)$。

#### D. 使用扩展模式 (Extensions Pattern) 减少传参
- **现状**：`group.ts` 等外部函数需要传递大量上下文参数（`nodeMap`, `updateNode` 等）。
- **建议**：将 Group 逻辑设计为 `CreateNodeContext` 的一个插件或扩展类。
- **代码示例**：
  ```typescript
  class CreateNodeContext {
    public group = new GroupExtension(this); 
  }

  class GroupExtension {
    constructor(private context: CreateNodeContext) {}
    execute() {
      this.context.updateNode(...); // 直接通过上下文访问
    }
  }
  ```
